# Implementation plan

## Specification and global constraints

Link the authoritative specification or state the concise behavior here. Include
acceptance IDs, compatibility, authorized effects, and relevant project conventions.

## Tasks

For each task record:

- Goal and acceptance criteria covered.
- Required behavior and important failure cases.
- Dependencies and interfaces with other tasks.
- Likely files and scope boundaries, allowing justified discoveries.
- Spec → red → green requirement for executable behavior.
- Focused checks and required integration evidence.

Choose cohesive tasks with clear boundaries. Group tiny edits of the same shape
when separate dispatch/review would add overhead without useful isolation.

## Completion

Define integrated acceptance checks and material limitations. Record the baseline,
task/review budget, and any restriction on commits or external actions. Implementation
plans do not grant new authorization beyond the user's task.
